# 한국어·영어·베트남어 표시 언어 (#866)

## 언어와 저장 경계

지원 언어는 registry의 `ko/en/vi`, 포맷은 `ko-KR/en-US/vi-VN`이다. 공통 언어 선택에서 한국어/English/Tiếng Việt를 고른다. 유효한 브라우저 저장값을 우선하고 없으면 navigator 선호 목록의 첫 지원 언어, 그 외 한국어를 사용한다. 선택은 `mastergantt.ui.locale` localStorage에 저장한다. 저장 접근이 거부되어도 현재 탭의 수동 선택과 기존 앱 사용은 유지한다. 새 서버 계정·인증 쿠키·사용자 DB 레코드를 만들지 않는다.

SSR/첫 hydration은 결정적인 한국어이며 mount 뒤 브라우저 선택과 html lang을 동기화한다. 언어 전환은 기존 컴포넌트를 갱신하고 Gantt를 locale key로 remount하지 않는다. 일정 원본·권한·선택/scroll/Day·Week·편집 초안은 유지한다. date-only/UTC·화면별 timezone·Project Effective Calendar·Monday/W##·duration/lag/공수 계산은 언어와 독립적이다.

고정 UI는 소스에 관리하는 정적 en/vi 사전을 사용하고 한국어 원문 키를 fallback으로 쓴다. 파라미터는 React의 텍스트로 렌더링하며 HTML로 삽입하지 않는다. API 필드/enum/error code·DB/FK·route·원본 taskId는 번역하지 않는다. Project/Task/Issue 내용·메모·사람 이름 등 자유 입력도 자동 번역하거나 저장 원문을 변경하지 않는다. 외부 번역 서비스/LLM 요청은 없다. SVAR2.7.3은 설치된 Locale/words의 gantt/core/calendar 사전을 사용한다.

## 기준정보 표시명

관리자는 기존 원본 이름과 별도의 선택형 한국어/영어/베트남어 표시명을 입력하고 명시적으로 저장/취소한다. Project Master의 이름셀 옆 번역 아이콘은 별도 dialog를 열며 닫힌 기본행의 밀도를 유지한다. Resource Group의 기존 inline 편집은 그대로다. dialog는 한국어 입력에 초기focus를 두고 Escape/취소 뒤 원래 trigger로 복원하며401재인증/412충돌의 초안을 보존한다. 비우고 저장하면 해당 번역을 제거한다. 읽기는 `translations[currentLocale]`의 유효값 또는 **정확한 원본 name**을 표시한다. 다른 언어의 번역으로 fallback하지 않는다. 검색은 원본과 현재 언어 표시명을 함께 확인하고 선택·수정에는 원본 ID/code를 사용한다. 번역명 중복 때문에 기존 고유성 규칙을 바꾸지 않는다.

| 원본 | 소유권/쓰기 권한 |
| --- | --- |
| 사업부/제품/사업장·법인, Process Type/제품 표준공정/현장공정/공유 WorkArea | 기존 글로벌 Project Master 관리자 |
| 설비 유형/물류 시스템 유형 | 기존 글로벌 Logistics 관리자 |
| Resource Group | 기존 글로벌 Resource 관리자; 개인 Resource 이름은 대상 제외 |
| Project 공정/직접 WorkArea/설비/물류 시스템 | 해당 Project 편집 세션 |

DB는 migration0036의 12개 owner별 번역 테이블을 추가하고 기존 name/ID/FK/UNIQUE/수량을 변경하거나 번역값을 backfill하지 않는다. 기존 CRUD의 Origin·revision·auth transaction을 재사용한다. DTO `name` 의미는 그대로이며 선택적 `translations`만 추가한다. 쓰기에서 생략은 보존, `{}`는 전체 해제다. 물류 유형의 생성·이름 수정에서는 번역을 변경하지 않았으면 필드를 생략하고, 추가·수정·전체 해제 시에만 전체 번역 집합을 명시적으로 전송한다. trim/NFC/200자·제어문자 검증과 owner FK/삭제 cascade를 적용한다. 사용 중 원본 삭제 방어는 기존 서비스가 유지한다.

Copy는 Project 소유 번역을 새 owner ID에 재매핑하고 전역 원본은 기존 참조를 유지한다. 번역이 있는 Template은 schemaVersion6으로 보존하고 기존2~5는 계속 읽는다. 지원하지 않는 schedule JSON/Excel 내보내기는 번역을 조용히 잃지 않도록 `DISPLAY_NAME_TRANSLATIONS_EXPORT_UNSUPPORTED`로 거부한다. DB rollback은 새 테이블만 지워 무손실이라고 가정하지 않고 대응 앱 버전과 사전 backup을 함께 복원한다.

## 확장과 검증

새 언어는 registry·정적 사전·SVAR 사전·표시명 validator/DB locale CHECK·편집 필드·테스트를 함께 확장한다. 키 누락/placeholder 불일치는 CI 사전 검사 대상이다. unknown 서버 오류는 허용 error code에 해당하는 안전한 문구로만 표시한다.

현재 사용자 Web 매뉴얼 제품 baseline은 #720 문서 정책 PR과 별개다. 이 변경은 해당 화면 언어 선택·표시명 편집·Issue 레이아웃을 본 문서 및 기존 화면별 가이드에 동기화한다. 구현되지 않은 `/manual` 화면을 존재한다고 안내하지 않는다. 실제 실행과 미검증/운영 환경은 [Work Packet](exec-plans/active/ISSUE_866.md) 및 [누적 원장](ISSUE_866_FAILURE_ANALYSIS.md)에서 구분한다.

## 오류의 업무 문맥과 안전 표시

오류 응답의 임의 `message`/`details.message`와 파서·네트워크 예외 문자열은 번역 키나 fallback으로 표시하지 않는다. 고정 코드 메시지와 검증된 식별자를 분리한다. 국가 캘린더 미확보는 고정 안내를 현재 언어로 번역하고, 정확한 국가 코드·연도 식별자만 제출한 국가 규칙과 날짜 범위에 대조해 표시한다. 자유 설명·미선택 국가·범위 밖 연도·잘못된 코드/경로는 제외한다. 연도는 숫자 그룹핑을 하지 않는 식별자이며 `2032`를 보존한다. Preview의 idle/pending/error/stale/ready 안내도 현재 언어로 바뀌고 언어 변경은 Preview/Save 요청을 만들지 않는다.

WBS는 JSON 파싱 실패와 네트워크 예외까지 전송 경계에서 안전한 오류로 바꾸며, dashboard와 details가 임의 `Error.message`를 표시하지 않는다. 요청 취소, 응답 출처·revision 검증, stale 차단과 재시도 복구는 유지한다. 실제 실행·한계는 [누적 원장](ISSUE_866_FAILURE_ANALYSIS.md)을 따른다.

리소스 캘린더 충돌도 번역된 완성 문자열을 상태로 저장하지 않는다. 검증된 날짜·대상 ID/종류·고정 enum과 로컬 이름을 보관하고 렌더 시 label만 현재 언어로 번역한다. 서버가 새로 생성한 규칙 UUID와 로컬 초안 key의 정확한 대응은 지원한다고 주장하지 않으며, 원시 규칙 문장 대신 현재 초안 규칙의 수정 경로를 제공한다.

## JSX 표시 문자열과 HTML entity

JSXText와 따옴표 JSX attribute의 entity는 JSX 컴파일러가 해석하지만, `t(...)` 또는 JSX expression에 전달하는 일반 JS 문자열은 entity를 해석하지 않는다. 정적 번역 키와 사전 값은 실제 표시 문자 `&`, `>`, 따옴표를 사용하고 encoded alias로 등록 여부 검사를 우회하지 않는다. 사전/정적 호출 검사에서 잔존 entity를 확인한다.

이 원칙은 정적 UI 자원 작성 규칙이다. 사용자 원문과 미등록 키 fallback·수동 표시명을 일괄 decode하지 않으며, XML/SVG/Excel serializer의 정상 escape를 제거하지 않는다. 번역 결과는 계속 React 텍스트로 표시하고 HTML 실행·runtime entity decoder를 추가하지 않는다.
