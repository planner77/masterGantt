# 구현 화면 검토와 순차 개선 — 2026-09-28

## 기준과 범위

로컬 main을 원격 `3802c1e6099819c06b388ef4ec37f132d2beea06` / `0.51.0`으로 fast-forward하고 의존성을 설치한 뒤 검토했다. DESIGN의 파란색 Light UI·system font·semantic token·compact workspace를 유지한다. 구현된 화면의 사용자 흐름과 오류 복구를 우선하며 전체 restyle은 하지 않는다.

사용자 요청 범위는 개선 사항별 Issue 등록 → 구현 → Local Fast Feedback → DOCUMENTATION_SYNC → 독립 QA → PR → CI 시작이다. 각 Issue가 이 단계에 도달한 뒤 다음 Issue로 진행한다. shared docs/version 충돌을 줄이기 위해 후속 PR의 base는 앞선 작업 branch로 연결한다. 원격 검사 완료는 모니터링하지 않으며 `quality/e2e/docker`를 NOT TESTED로 남긴다. 병합·릴리스·Issue 종료는 이 범위에 없다. 각 단계의 최신 PR/head/run은 해당 Issue의 PLAN/STATUS 기록을 따른다.

정식 릴리스는 `release_required=false`, `release_authorized=false`다. 이 묶음의 UI 결함 수정에는 Issue 순서대로 PATCH 버전을 배정하고 package/lock을 일치시킨다. 기존 #234 검색·구성원, #235 리소스 헤더/PR #241, #260 Workspace 필터/PR #262, #253 Baseline/PR #259, #258 연결 일정 재계산, #261 Calendar, #30 Import는 중복 구현하지 않는다.

## 실제 검토 근거

Manager·ui_ux·qa_docs가 역할을 나누어 source 및 실제 Chromium을 확인했다. Chromium 설치 build `1243`, 격리 개발 서버 `127.0.0.1:3105`와 synthetic fixture를 사용했다. 오류·지연·mutation은 browser route mock으로 재현했고 운영 데이터는 변경하지 않았다. 초기 CLI의 기본 Chrome 경로가 없어 설치된 Chromium을 지정했다. URL 확인, 정적 검토, 브라우저 동작을 구분하며 전체 접근성 인증이나 화면 전체 PASS로 확대하지 않는다.

각 Issue 본문에 현재 문제, 목표 배치·상태, 인수 기준, 소유권과 비범위를 기록했다. 기존 layout은 유지하면서 compact loading/error/retry row, native control, 공통 dialog/form primitive를 우선한다. 공통 state 기준은 아래와 같다.

- 조회 중: 상태를 알리고 아직 확인되지 않은 입력·결과의 mutation/drilldown을 잠근다.
- 성공: 해당 task/revision/필터의 응답으로만 편집·조회 동작을 허용한다.
- 정상 빈 데이터: 원인과 다음 행동을 안내한다. 오류를 빈 목록으로 표현하지 않는다.
- 실패: 초안을 보존하고 명시적 재시도를 제공한다. 권한·revision 오류는 기존 서버 계약대로 복구한다.
- keyboard: named control, visible focus, native activation, APG tab/radio, modal containment와 실제 호출 지점 복원을 확인한다.
- 좁은 화면·긴 문자열: 390/768/1024/1440px, 문서 overflow와 의도된 내부 scroll을 구분한다.

## 검증·문서 영향

구현별로 관련 E2E/fixture, typecheck/targeted lint 등 최소 로컬 검증을 수행한다. before/after 캡처는 기능 조작 증거와 함께 사용하며 스크린샷만으로 keyboard·권한·상태 보존을 판정하지 않는다. frontend 자체 결과와 qa_docs의 독립 준비 검토, PR의 원격 판정은 분리한다.

UI/오류 복구 계약은 PROJECT_UX/TASK_EDITOR/LOGISTICS_DASHBOARD와 TEST_PLAN의 관련 절에 반영한다. API/DB/SCHEDULING_ENGINE/SECURITY/IMPORT_SCHEMA/CI_CD/REMOTE_VALIDATION은 해당 외부 계약을 변경하지 않는 한 N/A이며, 변경이 필요해지면 Manager에게 반환한다. DESIGN/UI_UX_GUIDELINES의 기존 규칙을 적용하므로 새 시각 시스템·UI framework는 추가하지 않는다.
