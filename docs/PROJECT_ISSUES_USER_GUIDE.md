# 프로젝트 Issue 사용 가이드 — #838 / #839 / #840

## 목적과 접근
프로젝트 상세 화면의 **일정 옆 Issue 탭**은 일정 WBS의 Task와 관련된 현장 문제를 기록하는 독립 원장이다. GitHub 개발 이슈와 별개이며 Task의 일정·진척률·Milestone 완료 상태를 변경하지 않는다.

- 공개 프로젝트는 Issue 목록·내용을 조회할 수 있다. 비공개 프로젝트는 해당 프로젝트의 유효한 편집 세션이 있어야 읽을 수 있다.
- **Issue 등록·수정**은 기존 프로젝트 **편집 잠금 해제** 후 가능하다. 읽기 전용에서는 제목을 클릭해 상세를 볼 수 있지만 저장할 수 없다.
- 등록/수정은 프로젝트의 현재 revision에 종속된다. 다른 사용자가 먼저 변경했다면 412 충돌이 표시되고 최신 원본을 확인해야 한다.

## Issue 등록과 변경
1. 프로젝트의 **Issue** 탭 → **Issue 등록**.
2. **Issue 명**을 입력한다(필수, 160자 이내).
3. **등록일**은 서버 등록 시각 기준으로 자동 생성되며 수정할 수 없다. **발생일** 기본값은 Asia/Seoul의 오늘이며 사용자가 수정할 수 있다.
4. **등록자**와 **담당자**를 직접 입력하거나 **리소스 검색**에서 프로젝트 참여·배정 리소스를 선택한다. 선택 시 이름과 참조 ID를 함께 저장하고 직접 고치면 연결이 해제된다.
5. **관련 Task**도 직접 설명을 입력하거나 **Task 검색**으로 프로젝트 WBS Task/Summary/Milestone을 정확히 선택한다. 다른 프로젝트 Task는 참조할 수 없다.
6. **완료** 체크 시 해당 시점의 날짜가 자동 **완료일**이 되며 수동 변경 가능하다. 체크 해제 시 완료일을 비운다.
7. **Issue 내용**은 4,000자 이내의 줄바꿈 가능한 텍스트다. HTTP(S) URL은 링크 미리보기에서 클릭 가능하며 HTML 스크립트는 실행되지 않는다.
8. **등록**으로 저장한다. 목록에서 Issue 제목을 선택하면 상세·수정할 수 있다.

Task/리소스 원본이 삭제되면 원본 참조 ID는 자동 해제되지만 Issue의 당시 Task명/등록자/담당자 표시 텍스트는 보존된다.

## 검색·집계·목록
- 상단 완료율은 프로젝트 **전체 발생 Issue**를 모집단으로 하며 검색/페이지네이션과 무관한 **완료 N / 전체 M (P%)**로 표시한다. 전체 0건이면 0.0%다.
- 제목·내용·등록자·담당자·관련 Task 검색어와 상태 **전체 / 미완료 / 완료** 조건을 함께 적용한다. 검색 버튼과 초기화 버튼이 있다.
- 목록 컬럼: **Issue명 / 완료 여부 / 담당자 / 발생일 / 완료일**. 최신 등록 순으로 표시한다.
- 페이지당 **10 / 20 / 50 / 100건**, 이전·다음 이동. 조건·페이지 크기 변경 시 1페이지로 돌아간다.
- 검색 결과 없음과 전체 Issue 없음은 서로 다른 안내로 구별한다.
- Issue 변경 시 프로젝트 revision이 증가하므로 다른 편집 중 충돌에 주의한다.
