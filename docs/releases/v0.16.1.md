# masterGantt v0.16.1

Issue #67의 Docker Compose 리소스 관리자 비밀번호 전달 누락을 수정하는 하위 호환 PATCH 버전이다.

## 수정 내용

- `deploy/compose.yml`에서 `RESOURCE_CATALOG_ADMIN_PASSWORD`를 app 컨테이너 환경에 명시적으로 전달한다.
- `${RESOURCE_CATALOG_ADMIN_PASSWORD:?Set RESOURCE_CATALOG_ADMIN_PASSWORD}`를 사용해 값이 없으면 container 생성 전 Compose config 단계에서 실패한다.
- 애플리케이션의 기존 최소 16자 정책과 fail-closed 인증 정책은 변경하지 않는다.
- 실제 관리자 비밀번호를 로그에 출력하지 않는다.

## 회귀 검증

CI Docker smoke는 다음 계약을 자동 확인한다.

- 비밀번호 미설정 상태의 `docker compose config` 실패
- 렌더링된 Compose app 환경에 관리자 비밀번호가 전달됨
- 실행 중 container에서 올바른 비밀번호 인증은 201, 잘못된 비밀번호 인증은 401
- 인증 요청 직후 및 container 재생성 후 로그에 정상/오류 입력 비밀번호 원문이 포함되지 않음
- 기존 readiness, restart/recreate 및 SQLite volume persistence 유지

## 버전 정책

공개 API/DB schema를 추가하지 않고 기존 Docker 배포 결함만 수정하므로 Semantic Versioning PATCH 변경으로 `0.16.0`에서 `0.16.1`로 증가한다. `package.json`과 `package-lock.json`의 version을 동일하게 유지한다.

## 운영 적용

`.env`에 최소 16자 이상의 `RESOURCE_CATALOG_ADMIN_PASSWORD`를 설정한 뒤 다음과 같이 config를 먼저 검증하고 app container를 재생성한다.

```sh
docker compose --env-file .env -f deploy/compose.yml config --quiet
docker compose --env-file .env -f deploy/compose.yml up -d --force-recreate app
```

`--env-file`은 Compose 변수 치환 입력이며 모든 값을 자동으로 container environment에 전달하지 않는다. 이번 버전부터 Compose 파일이 해당 비밀번호를 명시적으로 전달한다.
