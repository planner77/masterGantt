# masterGantt v0.26.0

Issue #99의 프로젝트 편집/리소스 관리 비밀번호 정책 완화와 권한자 비밀번호 변경 기능을 포함하는 하위 호환 MINOR 릴리스다.

## 변경 내용

- Project 생성·복사·비밀번호 변경의 신규 비밀번호 정책을 1~12 Unicode 문자로 통일한다.
- 기존 Project의 장문 비밀번호는 unlock/삭제 재인증에서 계속 사용할 수 있어 기존 데이터의 접근을 막지 않는다.
- 유효한 Resource catalog 관리자 세션에서 관리자 비밀번호를 변경할 수 있다.
- Resource 관리자 비밀번호는 SQLite에 scrypt 파생값으로 저장하며 원문은 저장하지 않는다.
- `RESOURCE_CATALOG_ADMIN_PASSWORD`는 DB 자격증명이 없을 때의 최초 seed로만 사용한다. 신규 설치는 1~12자를 사용하고, 기존 16자 이상 값은 업그레이드 최초 로그인에서 legacy migration seed로 허용한다.
- 런타임 변경 후에는 환경변수 변경이나 컨테이너 재생성으로 DB 자격증명을 덮어쓰지 않는다.
- Resource 관리자 비밀번호 변경 시 기존 관리자 세션을 모두 revoke하고 호출자에게 새 세션을 발급한다. credential row가 아직 없는 업그레이드 세션에서도 upsert로 새 값이 반드시 저장된다.
- SQLite migration `0007_resource_admin_credentials.sql`을 추가한다.
- Issue #84의 Project List 검색/필터 기능을 유지하면서 삭제 재인증의 기존 장문/신규 단문 비밀번호 호환을 보존한다.

## 검증 범위

- 12자 설정 성공 / 13자 거부 / 짧은 비밀번호 허용
- Project·Resource 권한 영역 분리와 무권한 변경 거부
- 변경 전 Resource 비밀번호 재인증 실패 / 변경 후 성공
- 재시작 후 Resource 관리자 자격증명 유지
- 환경변수 seed 우선순위
- 비밀번호 원문 로그·응답 비노출
- Project 생성/복사/unlock/삭제 재인증 회귀
- Chromium E2E 및 Docker production HTTP/HTTPS·SQLite restart/Compose smoke
- Resource 관리자 로그인 KDF 앞의 process-global 20회/15분 rate limit

## 통합 기준

- 최신 `main`의 CI/CD 문서 및 Issue #84 release-helper 변경을 포함한 상태에서 최종 회귀 검증한다.

## 배포

기존 SQLite volume을 유지하면 startup migration에서 `0007_resource_admin_credentials.sql`이 순차 적용된다. Resource 관리자 DB 자격증명이 아직 없으면 최초 정상 관리자 인증 때 환경변수 seed를 해시해 저장한다. 기존 배포의 장문 환경변수도 이 한정된 bootstrap 경로에서는 호환되며, 신규/변경 비밀번호는 1~12자다. 이후 UI에서 변경한 비밀번호가 우선한다.
