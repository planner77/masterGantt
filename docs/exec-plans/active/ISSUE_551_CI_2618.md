## 실패 원인과 이전 실패의 구별

TypeScript, ESLint, Vitest, 정책 검사, Next production build, Docker 및 Chromium E2E 6개 shard와 필수 3개 aggregate는 모두 SUCCESS다. 이번 실행은 #2613.3의 대형 fixture readiness timeout 재발이 아니다. 다만 이번 한 번의 성공을 장기 안정성 보장으로 해석하지 않는다.

QA Final — Automated의 직접 차단 사유는 `mergeability 또는 test merge 불일치`다. 신뢰된 base의 `scripts/qa_final_automated.py::snapshot`은 `live.mergeable is True`와 `live.merge_commit_sha == TEST_MERGE_SHA`를 동시에 요구한다. 이 복합 조건이 실패했다. 실패 당시 live API 응답의 mergeable·merge SHA 값은 로그에 포함되지 않아 둘 중 어떤 값이 조건을 위반했는지 소급 확정할 수 없다.

원본 CI의 base/test-merge가 고정된 상태에서 main이 전진했다는 사실과 시험 병합 부모는 별도로 확인했다. 사후 PR 조회가 다시 mergeable=true를 반환하더라도 원본 QA 실패를 PASS로 바꾸거나 당시 상태가 정상이었다고 주장하지 않는다. 검증 중 main 변경 및 시험 병합 재계산 경합을 먼저 해소하는 것이 이번 운영 교정이다.

#2613.2의 QA-only 재시도는 최신 attempt의 `ci-pr-source` artifact 누락으로 Trusted QA가 차단되었다. #2613.3은 readiness 실패와 QA context 불일치를 포함했다. #2618.1은 애플리케이션 검증 SUCCESS / QA context BLOCKED로 각각 구별한다.

## 교정 절차

1. 기존 성공한 Milestone 제품 코드, 대형 fixture, 5초 준비 검사, 좌표 ±1px, 6 shard, retry/skip 및 필수 gate를 변경하지 않는다.
2. 최신 main과 PR Head를 실조회하고 새 `pull_request` 이벤트를 발생시켜 최신 base와 test merge를 새 run의 출처로 고정한다. 원본 #2618의 실패 Job만 재실행하는 방식은 사용하지 않는다.
3. GitHub가 생성한 최신 test-merge를 사용할 때는 두 부모가 정확히 현재 main/PR Head인지 확인한다. main 정렬용 tree로 사용할 경우에도 이 부모 확인 없이 과거 merge tree를 사용하지 않는다. 원본 #551 및 #645의 문서·코드 양쪽을 보존한다.
4. 게시 후 실제 PR Head/base, mergeability, test-merge 부모와 새 CI Run ID/attempt/Head를 확인한다. 새 Run 등록 확인 후 결과 모니터링은 요청 범위 밖이다.
5. 검증 도중 main이 다시 변경되면 새로운 통합 기준이 필요할 수 있다. 이러한 경합을 허용하려고 검증기의 SHA/mergeability 검사를 끄거나 과거 성공을 승계하지 않는다. 최종 병합 검증 구간에서는 관련 PR 병합 순서를 조정해야 한다.

## 검증과 제한

- 조회한 `snapshot` 함수의 동일 조건을 이용한 오프라인 합성 입력 6건을 실행했다: 일치하는 원본 context, mergeable=null, mergeable=false, 다른 test-merge SHA, 다른 base SHA, 새 base/test-merge에 맞는 새 event. 각각 기대한 PASS 또는 BLOCKED와 일치했다.
- 이 6건은 조건 수준의 합성 검증이며 저장소 전체 Python suite, 실제 GitHub API 경합 재현 또는 새 원격 CI 성공 증거가 아니다. 실제 실패 당시의 live 응답 값을 복원한 것도 아니다.
- 로컬 전체 브라우저/Build/Docker는 이번 운영·문서 교정에서 재실행하지 않았다. 기존 제품 검증 SUCCESS는 원본 #2618.1에만 귀속되며 새 Head의 공식 CI/Trusted QA/Owner ACCEPT는 별도 증거 전 NOT TESTED다.
- DOCUMENTATION_SYNC: 본 후속 실행 기록 추가. 기존 Work Packet의 AC_TEST_COVERAGE와 제품 문서의 기능 계약은 유지한다. DESIGN/UI_UX/API/DB/Scheduling/보안·배포 계약 변경 N/A. 상위 main의 #645 변경은 그대로 보존한다.
- risk_level=HIGH, qa_method=OWNER_MANAGED, release_required=true, release_authorized=false. 최종 QA/Owner 승인, PR 병합/Main CI/GHCR 게시/Issue 종료는 이번 요청으로 수행하거나 PASS로 선언하지 않는다.
