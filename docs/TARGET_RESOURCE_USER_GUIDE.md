# 공정·설비·물류 시스템과 리소스 사용자 가이드

## Issue #792 — 이전 Summary 관계의 적용 범위를 수정할 때

이전 버전에서 만든 기존 물류 Target 연결은 Task 편집의 **기존 연결 출처**에서 실제 설비·System과 원본 작업, 적용 범위/전체·선택 구성/coverage를 확인합니다. 신규 업무의 직접 설비·시스템 체크박스는 이 보존된 관계를 변경하지 않습니다. 기존 Summary에 직접 저장된 원본 연결이 있을 때만 아래 절차로 **범위만** 수정할 수 있습니다.

1. 프로젝트 **편집 권한**을 연 다음 Summary 작업을 선택하고 물류 연결 편집에서 기존 출처를 확인합니다.
2. `기존 관계 적용 범위 수정`을 선택하고 원본 관계를 확인한 뒤 `이 작업만` 또는 `하위 작업 포함`을 선택합니다. 원본 선택/전체 구성, 장비 수량·coverage, Task/설비·System ID는 수정되지 않습니다.
3. `영향 미리보기`에서 변경될 작업 건수·구성원 건수와 범위 전환을 검토하고 `영향을 확인하고 적용`을 누릅니다. 프로젝트 Revision·출처·편집 세션이 바뀌었거나 다른 편집 초안이 저장되지 않았다면 최신 상태를 다시 읽습니다.
4. 변경 취소가 필요하면 별도로 원래 범위를 재선택해 영향 재검토 후 적용합니다. 원본을 임의 삭제/복사하거나 직접 체크박스로 평탄화하지 않습니다.

이 기능은 **Summary의 기존 직접 관계 적용 범위만** 허용합니다. 상속된 자손 관계는 상위 출처에서 관리하고, 원본 선택 구성 변경·coverage 수정·기존 Target 삭제·대규모 운영 이관은 지원되지 않습니다. 권한 오류/409/412/422는 성공이 아니며 운영 데이터 수정 전 담당자가 원본 백업과 외부 소비자 영향을 확인해야 합니다. [Task Editor](TASK_EDITOR.md), [운영·복구](TARGET_RESOURCE_OPERATIONS.md).

프로젝트의 같은 WBS Task와 개인 Assignment를 공정·작업 구역·설비·물류 시스템·Milestone·리소스 관점으로 조회합니다. 기준정보나 조회 행을 만들었다고 작업·배정·공수가 생기지 않습니다. 동일한 실물을 경로마다 복제하지 마세요.

## 탐색과 전체 일정 복귀

상위 탭은 **일정 / 대시보드 / 기준정보**입니다. 대시보드는 **KPI / Milestone / 공정&WorkArea / 설비 / 물류 시스템 / 리소스**, 기준정보는 **공정&WorkArea / 설비 / 물류 시스템 / 리소스** 순서입니다. 조회는 대시보드, 실물 등록·수정은 기준정보를 사용합니다.

일정은 전체 WBS를 기본으로 표시합니다. Summary 범위 탭과 명시적인 전체 일정 보기로 범위를 선택합니다. 대시보드에서 작업을 열거나 일정으로 이동한 뒤 돌아오면 출발 보기·선택·상세를 확인하세요. 일반 탭 이동은 전체 일정 범위를 새로 선택하는 동작과 다릅니다. 오래된 화면 링크나 저장 설정은 유효한 공정/작업 구역 화면으로 복구됩니다.

## 1. 프로젝트와 구성 준비

프로젝트를 만들고 편집 권한을 연 뒤 기준정보에서 공정·WorkArea·설비·물류 시스템을 등록합니다. 공정과 구역은 없어도 정상입니다. 분류·공정 유형·제품 표준·사업장 매핑을 신규 공정의 필수 선행 단계로 만들지 않습니다.

설비는 실제 인스턴스와 수량을, 시스템은 실제 인스턴스와 controller/coordinator 역할을 구분합니다. 공통 MCS를 여러 공정에서 사용해도 같은 시스템 원본 하나를 연결합니다. 이름이 같더라도 서로 다른 ID의 원본을 자동 합치지 않습니다. 사람은 기존 전역 Resource를 재사용하고 프로젝트 등록·책임 역할·Task 개인 배정을 구분합니다.

## 공정·WorkArea 관리

`기준정보 → 공정&WorkArea`에서 공정을 추가하고 선택 공정의 WorkArea를 관리합니다. 한 구역은 한 프로젝트 공정에 직접 소속되며, 공정당 구역 0개도 정상입니다. 다른 공정에 같은 이름의 구역이 있어도 별도 원본입니다. 사용 중 삭제나 소속 공정 변경이 거부되면 기존 연결을 먼저 확인하세요.

이전 공통 구역은 명시된 매핑의 기존 참조로 조회됩니다. 프로젝트 편집 권한은 전역 관리자 권한이 아닙니다. 공유 구역을 프로젝트별로 복제하거나 이름으로 재연결하지 마세요.

## Issue #725 — 공정·WorkArea와 설비 구역 관리

공정/구역의 실제 소속과 작업에서 선택한 업무 문맥은 다릅니다. Task/Summary의 공정은 0개 이상 직접 선택하며, 설비나 시스템을 선택했다고 Task 공정을 자동 채우지 않습니다. 구역은 실제 소속 공정과 함께 선택합니다. 선택0개와 아직 명시 선택을 도입하지 않은 이전 자료는 다르게 해석될 수 있습니다.

## 설비의 연결 WorkArea

설비 하나는 서로 다른 공정의 구역 여러 개에 연결할 수 있습니다. 주 관리 공정과 연결 구역의 공정은 같지 않아도 됩니다. 수량10인 설비가 두 구역에 연결되면 구역별 관련 수량은 각각10일 수 있지만 프로젝트 고유 수량은10입니다. 이는 구역별 실제 배치 수량을 뜻하지 않습니다.

## 설비와 물류 시스템 원본 관리

`기준정보 → 설비 / 물류 시스템`에서 실제 이름·유형·수량·활성·책임 역할·공정/구역을 관리합니다. 설비와 시스템의 실제 제어·조율 관계는 Task의 업무상 동시 연결과 다릅니다. 공유 원본을 바꾸면 정확한 관련 작업과 영향을 확인하고 저장하세요. 관계 해제와 실물 삭제는 서로 다른 동작입니다.

## 같은 Task에 직접 연결

Task Editor의 물류 연결에서 직접 공정·작업 구역과 설비·시스템을 선택합니다. Summary 범위를 자신의 작업 또는 하위 작업까지 적용할지 확인하세요. 개인 배정은 리소스 탭에서 관리합니다. 한 업무에 설비와 시스템이 함께 필요하면 같은 Task에 연결하며 조회 관점별로 Task를 복제하지 않습니다.

**기존 연결 출처**는 실물별 원본 작업·자신/하위 범위·전체/선택 구성·coverage와 출처 공정/WorkArea를 읽기 전용으로 보여줍니다. 출처 문맥은 Task에서 직접 선택한 공정/구역과 다릅니다. 직접 체크박스와 별도 원본이므로 자동 체크·변환하지 않습니다. 전체 구성은 구성원이 바뀌면 해석 범위가 달라질 수 있고, 선택 구성은 명시한 실물만 포함합니다. coverage는 작업 관련 수량이며 실제 설비 수량이나 공수 배율이 아닙니다. 기존 출처 자체 편집이 지원되지 않는 경우 이를 직접 선택 삭제로 해제할 수 있다고 가정하지 마세요.

조회 오류·충돌을 빈 연결로 저장하지 마세요. revision이 바뀌면 최신 자료를 다시 읽고 초안을 확인합니다. 저장·취소·다른 보기 왕복에서 같은 작업과 원본 ID를 확인하세요.

## 2. 같은 Task의 여러 실물 연결

담당·기간·완료 기준이 같은 통합 업무는 하나의 Task에 필요한 실물을 연결합니다. 실제 업무가 다를 때만 Task를 나눕니다. 시스템만 선택한 연결을 같은 구성의 다른 설비까지 넓히지 않습니다. Summary 상속은 하위 Task마다 복사한 직접 관계가 아니며 원본 작업과 적용 범위를 확인해야 합니다.

## 설비 현황

`대시보드 → 설비`에서 설비를 최상위로 조회합니다. 하위 없는 요약 또는 공정/WorkArea·물류 시스템·Milestone·리소스 하위 축을 선택합니다. 유형·이름으로 좁히고 작업0·미배정·비활성 기존 참조를 구분합니다.

등록 수량·원본 속성과 관련 Task의 진척·계획공수는 다른 지표입니다. 여러 구역·Milestone을 거친 소계를 더하지 말고 서버 고유 총계를 읽으세요. 정확 상세에서 원본 작업/배정을 열거나 설비 기준정보로 이동합니다.

## 물류 시스템 현황

`대시보드 → 물류 시스템`에서 System 인스턴스를 조회합니다. 직접 연결과 조율 범위 포함을 구분하고 유형·계층·공통/공정 범위·PI/개발자 속성을 확인합니다. 업무상 같은 Task에 연결된 설비가 실제 제어 설비라는 뜻은 아닙니다.

공유 MCS와 같은 작업/배정은 원본 ID로 중복 제거합니다. 관련 시스템 수·제어 설비량과 일반 Task 진척·계획공수·전체 Milestone Gate를 서로 대신하지 마세요. 역할은 계획상의 책임이며 실제 수행 인원·가동률의 증거가 아닙니다.

## 공정과 WorkArea 현황

`대시보드 → 공정&WorkArea`에서 공정 또는 작업 구역과 하위 축을 선택합니다. 구역0개·명시 공정0개·등록만 있는 원본은 정상 상태입니다. Task의 명시 공정과 설비의 주 관리 공정·구역 소속을 구분합니다.

구역별로 같은 실물이 반복되어도 전체 고유 수량을 늘리지 않습니다. 공유 시스템/Milestone 아래를 열면 앞에서 선택한 같은 Task/Assignment 교집합을 유지하며 다른 작업으로 넓히지 않습니다. 전체 Milestone 완료 조건은 선택된 부분의 진척과 별도로 확인합니다.

## 동적 조회 구성과 정확 상세

최상위 관점을 고정하고 하위 축을 추가·삭제·재정렬하거나 단독 요약으로 돌아갑니다. 설비와 시스템 형제는 실제 부모/자식 저장 관계가 아닙니다. 조회 설정 변경은 WBS·기준정보·Task·Assignment를 만들거나 재배치하지 않습니다.

표시 행 key와 원본 Task/Assignment ID는 다릅니다. 상세에서 실제 작업/배정을 확인하고 해당 원본만 편집합니다. 조회/상세 snapshot이 오래되면 다시 조회하세요. 지원하지 않는 Excel 조합은 조건을 버린 전체 보고서로 대체하지 않고 오류로 안내합니다.

## KPI와 구성·연결 진단

KPI는 같은 WBS 원장에서 일반 Task·개인 배정·실물의 고유 집합을 읽습니다. 미배정/공수 미설정·등록만 있는 실물·작업 문맥 미선택을 구분합니다. 공정/구역/설비/시스템의 실제 연결과 작업 연관을 추정해서 채우지 않습니다.

일반 Task 진척/완료·지연, 개인 계획 M/D/M/M, 등록 인원, 실물 수량, Capacity는 모집단이 다릅니다. 기간이 없는 작업·미산정 값은 0으로 바꾸지 않습니다. 전체 Milestone Gate는 전체 원본 작업과 선행 조건을 사용합니다.

## 리소스 중심 분석과 기존 Plan

`대시보드 → 리소스`의 동적 관점과 기본 현황·Group/Role/등급·Milestone·주/월 Plan·견적·Excel을 사용합니다. 두 조회의 독립 필터가 같은 조건이라고 가정하지 말고 현재 출처/선택 범위를 확인하세요. 정확 Assignment 상세는 같은 Task의 공동담당자 전체로 확대하지 않습니다.

## 4. 원본 편집과 복귀

Task 행은 기존 Task Editor에서 이름·일정·상태·진척·직접 연결을 수정합니다. 정확 Assignment 행은 표시된 개인/Assignment ID의 배정만 수정합니다. 실물 이름·수량·제어관계는 해당 기준정보에서 변경합니다. 가상 조회 헤더·총계는 저장 원본이 아닙니다.

readonly에서는 조회만 가능합니다. dirty 초안·pending·401/403·stale409/412를 확인하고 갱신/취소를 선택하세요. 닫기는 보이는 출발 trigger로 돌아가며, 그 trigger가 없어졌으면 같은 화면의 유효한 탭/제목으로 복귀합니다.

## 5. 주·월 Plan과 과투입 원인

같은 개인의 선택 부하80%와 프로젝트 전체140%는 서로 다른 범위입니다. 선택 조건이 Capacity R나 프로젝트 전체 참고를 줄이지 않습니다. 개인별 일별 Peak·과투입을 Group 평균이나 기간 합계로 숨기지 마세요.

기간→개인→정확 Assignment를 열어 원인을 확인합니다. 프로젝트 전체에서 선택 밖 원인을 수정한 뒤 원래 조건으로 돌아올 수 있습니다. 날짜·Calendar·가용량·수량/공수 단위를 함께 확인하세요.

## 6. Excel과 안전한 교환

현재 조건 또는 명시 프로젝트 전체 범위로 내보냅니다. 조회와 같은 snapshot·Task/Assignment ID·실물 ID·출처·raw/null·M/D/M/M을 확인하고 반복 출처 행을 재합산하지 않습니다. 실물 구성·관련 작업·배정 근거 시트는 보고서이며 DB backup이 아닙니다.

일정 JSON1.0/1.1과 일반 일정 Excel은 전체 물류/리소스 관계를 표현하지 못합니다. 미지원 오류가 나오면 일부 데이터를 삭제하는 우회 대신 지원되는 전체 Project Copy/Template 또는 운영 backup 절차를 사용하세요. 구형 파일이 지원되지 않으면 전체 실패하며 일부 성공으로 안내하지 않습니다.

## 프로젝트 리소스 등록과 해제

`기준정보 → 리소스`에서 기존 전역 사람을 프로젝트에 등록합니다. 등록-only·책임 역할-only·개인 배정을 구분하고 미배정 등록자도 저장 후 유지됩니다. 같은 사람을 여러 프로젝트에 등록해도 사람 원본은 늘어나지 않습니다.

등록은 편집 ACL·Task 배정·실제 수행/근무 실적이 아닙니다. 등록·해제만으로 Task·계획공수·기존 Capacity를 바꾸지 않습니다. 사용 중 해제나 전역 삭제는 기존 참조를 확인하고 차단될 수 있습니다. 전역 수정에는 별도 관리자 권한이 필요합니다.

## Milestone 추가와 동적 관점

Milestone은 작업 완료 확인 지점입니다. Ready와 Completed는 다르며 선택 Task의 진척만으로 전체 Gate를 완료 처리하지 않습니다. 표시·필터와 canonical 소속·선행 조건을 구분하고 지원되는 추가/소속 관리·정확 작업 상세를 사용합니다.
