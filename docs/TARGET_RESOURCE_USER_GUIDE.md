## Issue #729 — 새 다관점 API와 현재 화면의 구분

신규 WBS 기반 조회 API는 Task가 직접 선택한 공정0..N을 사용한다. 공정 미연결도 정상이며 같은 Task의 설비·System·Resource·Milestone 관련 작업은 계속 조회할 수 있다. 설비 주 관리 공정·System 담당 공정·설비 연결 구역이 Task 공정을 자동 결정하지 않는다. 기존 화면의 자동 유도 공정 수치와 새 명시 Task 공정 수치가 다를 수 있으므로 출처와 snapshot을 함께 확인한다.

설비/System 형제 분기·다관점 단계·등록-only root API는 공통 조회 기반이다. #729는 API만 도입했으며, #730의 현재 화면은 [동적 조회 구성과 정확 상세](#동적-조회-구성과-정확-상세)에서 설명한다. 여러 구역·Group·Milestone 소계는 겹칠 수 있으며 상위 고유 합계가 기준이다. 다른 경로의 작업이 섞이지 않도록 정확 상세는 선택한 경로와 같은 snapshot을 요구한다. stale 오류 시 최신 보고서를 조회한 뒤 다시 선택한다.

신규 동적 spec의 Excel은 현재 미지원이다. 기존 Resource 보고서 기능은 그대로이며 새 spec의 조건을 생략한 workbook을 같은 보고서로 취급하지 않는다. 연계 API에서 `taskSources`는 원본 Task 근거이며, 클릭한 경로의 정확 기여는 `selectedSources`와 typed `instanceIds/instancePaths`로 받는다. 원본 구성 출처를 선택된 작업으로 확대하지 않는다. 개발 연계의 실제 wire/한도는 [API](API.md#issue-729--versioned-wbs-다관점-조회), 실행/미검증 범위는 [Work Packet](exec-plans/active/ISSUE_729.md)을 확인한다. #720 매뉴얼에는 기존 anchor와 #730 동적 조회 안내를 인계한다. 앱 내 매뉴얼 route는 별도 후속 범위다.

## Issue #726 — Target 없이 같은 원본 연결

### 설비와 물류 시스템 원본 관리

`기준정보 → 설비 / 물류 시스템`에서 기존 목록의 검색·활성 조건과 추가/수정·담당 역할·제어/조율 관계를 사용한다. AMR A10/B5는 원본 Fleet 두 개, ACS A/B와 공유 MCS1은 System 원본 세 개로 등록하고 같은 ID를 작업과 다른 보기에서 재사용한다. 단품은1대, Fleet은 양의 정수이며 시스템은1식이다. 공유 원본의 수량·역할·관계 수정은 사용처 영향을 확인한다. Target에서 구성원만 빼는 것과 원본 삭제는 다른 명령이며 사용 중 원본 삭제는 서버가 차단한다.

유형 선택 옆에서 조회 중·조회 실패·활성 유형 없음·미선택 이유를 확인한다. 실패 시 `유형 목록 다시 시도`를 사용하고 활성 유형이 없으면 공통 기준정보 관리자에게 등록/활성화를 요청한다. Project 편집자는 유형을 사용해 설비/System을 생성할 수 있으며 이때 전역 관리자 로그인을 추가로 요구하지 않는다. 공정 한정 System은 같은 창에서 담당 공정1..N개를 명시 선택한다. 프로젝트 공통은 공정 목록을 비우고 저장한다. System 창도 Escape/취소 시 저장하지 않은 변경의 폐기 여부를 묻는다.

### 같은 Task에 직접 연결

기존 Task를 열고 `물류 연결`에서 직접 공정·작업 구역과 설비·물류 시스템을 선택해 각 영역을 저장한다. 공정은0개 이상, 설비 WorkArea는0개 이상이며 구역을 사용하면 실제 소유 공정을 명시한다. Task 공정을 설비/System/Target에서 자동 지정하지 않으므로 같은 공유 MCS를 A작업/B작업/통합작업에 반복 복제할 필요가 없다. 개인 배정은 리소스 탭에서 한다. MCS 연결은 관련 시스템 지정이며 공수 배분율이나 자동 제어관계가 아니다.

기존 공정 미설정과 명시0개는 다르다. 미설정 상태를 그대로 두거나 `공정 0개로 명시 설정` 후 저장한다. Summary 공정의 `하위 작업 포함`은 상위 설정 출처로 안내하며 Task의 명시 선택을 자동으로 채우지 않는다. 설비/System의 기존 subtree 합집합 상속은 유지하며 직접 선택과 상위 출처를 구별한다. 한 영역의 초안은 다른 영역을 잠그므로 저장하거나 명시 폐기 후 다음 영역을 편집한다. stale·권한 만료·조회 실패는 초안을 보존하고 안내에 따라 최신 정보를 다시 불러오거나 권한을 복구한다.

기존 Target-only 또는 혼합 연결은 `Target 연결 (기존 호환)`을 펼쳐 whole/subset·coverage를 계속 편집한다. 직접 연결과 Target는 별도 경로이며 화면 전환으로 자동 복사·변환하지 않는다. Target0개 프로젝트에서도 직접 작업 연결은 가능하다. 저장 후 재조회에서 같은 원본을 확인한다. 현재/원격 검증 상태는 [실행 원장](exec-plans/active/ISSUE_726.md)을 따른다. 이 절은 #720 매뉴얼 anchor 인계이며 앱 내 매뉴얼 route 추가가 아니다.

## Issue #725 — 공정·WorkArea와 설비 구역 관리

### 공정·WorkArea 관리

`기준정보 → 공정&WorkArea`(`screen=master.processes`)에서 Project 공정을 등록·수정하고 유효한 사업부/제품/사업장 문맥의 사업장 공정에 명시 매핑한다. 공정 코드는 자동 생성할 수 있고 기존 자유 계층과 미매핑 공정을 보존한다. `공정 매핑 기본 구역 (호환)`은 해당 매핑의 선택값이며 모든 설비/Task의 구역이 아니다. WorkArea 없는 공정도 정상이고 Target를 먼저 만들 필요가 없다.

공통 관리 영역은 별도 관리자 로그인 후 공정 유형·제품 표준·사업장 공정·WorkArea를 등록·검색·정렬·활성/비활성·사용량 확인·안전 삭제한다. 표준 적용은 사업부/제품/사업장을 고른 뒤 적용할 표준을 명시 선택한다. 다른 사업장이나 기존 Project 공정을 이름만으로 자동 변경하지 않는다. 관리자 기준정보 변경 뒤 `변경된 기준정보 적용` 등 명시 갱신을 통해 현재 편집 문맥을 다시 확인한다. Project 편집 비밀번호로 공통 카탈로그를 수정할 수 없다.

### 설비의 연결 WorkArea

`기준정보 → 설비`(`screen=master.equipment`)의 설비 추가/수정에서 **주 관리 공정**과 **연결 WorkArea(선택)**를 따로 고른다. 구역은0개·1개·여러 개가 가능하고 서로 다른 공정 구역을 함께 선택할 수 있다. 같은 이름은 소유 공정과 code로 구별한다. 전체 연결 해제를 누른 뒤 저장하면 구역 관계만 해제되고 설비·수량·연결 Task는 남는다.

공정이 아직 없으면 `+ 설비 추가`를 눌러도 설비가 생성되거나 입력 창이 열리지 않는다. 현재 영역의 지속 오류 안내를 확인하고 `기준정보 → 공정&WorkArea`에서 공정을 먼저 등록한 뒤 다시 추가한다. Target 등록은 이 흐름의 선행 조건이 아니다.


AMR Fleet E10을 조립 WA-A와 검사 WA-B에 함께 연결해도 설비 원본1개·수량10이다. 두 구역 관련 수량을 더해20대로 읽거나 실제 구역별 배치 대수로 간주하지 않는다. 공정/설비 구성을 바꿔도 Task의 선택 공정을 자동 변경하지 않는다. Task 공정0개도 정상이며 Task Editor의 물류 연결에서 직접 선택한다.

조회 실패·기준 변경·권한 만료 시 빈 목록으로 추측 저장하지 말고 갱신 후 다시 확인한다. Task 직접 연결/Target 구성에서 사용 중인 설비의 구역 관계 변경과 사용 중 삭제·소유 공정 변경은 거부될 수 있으며 비활성 기존 참조는 표시를 유지한다. Copy/지원 Templatev4는 다중 관계와 명시0개를 보존하지만 일정 JSON/plain 일정 Excel은 해당 정보가 있으면 손실 방지를 위해 Export를 거부한다. 명시 Resource 보고서 Excel은 기존 보고 범위로 허용하며 전체 backup이 아니다.

이 문서는 #720 매뉴얼의 기능 anchor 인계용이며 앱 내 `/manual` route·매뉴얼 버튼을 구현했다는 뜻은 아니다. `master.processes`와 `master.equipment`는 위 두 하위 절에 각각 연결한다. [API](API.md#issue-725--target-없는-공정workarea-직접-문맥)와 [실행 원장](exec-plans/active/ISSUE_725.md)에서 정확 계약과 검증 상태를 확인한다.

## 탐색과 전체 일정 복귀

상위 메뉴는 `일정 / 대시보드 / 기준정보`다. 대시보드에는 `KPI / Milestone / 공정&WorkArea / 설비 / 물류 시스템 / 리소스`, 기준정보에는 `공정&WorkArea / 설비 / 물류 시스템 / 리소스`가 있다. 분석은 조회와 정확한 원본 편집 진입, 기준정보는 원본 등록·수정에 사용한다.

`일정`은 기본 전체 WBS를 보여 준다. Summary의 `최상위로 열기`로 여러 범위 탭을 열 수 있고 한 번에 하나를 선택한다. `전체 일정 보기`로 전체 scope에 돌아가며 열린 Summary 탭은 남는다. 마지막 Summary 탭을 닫아도 전체 일정이 표시된다. 일반 `일정` 탭 왕복이나 분석의 원래 보기 복귀는 기존 scope·검색·필터를 유지한다. 중복 `전체 프로젝트` 하위 탭은 없다. `rootTask`가 있는 공유 링크는 해당 Summary로 바로 열린다.

Milestone 추가·소속 관리·Ready/Completed는 `대시보드 → Milestone`, 기존 KPI는 `대시보드 → KPI`, Resource Plan·Excel은 `대시보드 → 리소스`에서 이용한다. 기준정보의 `리소스`에서는 기존 전역 리소스를 프로젝트에 등록·해제한다. 원본 생성·수정은 `/resources`의 독립 관리자 로그인을 사용한다. Project 편집 권한만으로 전역 카탈로그를 수정할 수 없으며, 개인의 작업 배정은 기존 Task Editor의 리소스 탭에서 관리한다.

원본 관리/분석 이동으로 Task나 Assignment를 복제하지 않는다. Task·Assignment 편집기는 해당 화면에서 바로 열리고 저장·취소 뒤 출발 화면으로 복귀한다. 각 화면의 검색·기간·접힘과 Gantt의 Day/Week·스크롤·선택은 기존 계약을 유지한다. Tab/Arrow/Home/End로 메뉴를 이동하고 Escape는 열린 상세/대화상자를 닫는다. 숨은 panel로 focus가 이동하지 않는다.

이 문서는 저장소 사용자 가이드다. #720의 앱 내 `/manual`·화면별 매뉴얼 버튼은 이 변경에 포함되지 않는다. screenKey/이전 경로/향후 anchor 인계는 [Project UX](PROJECT_UX.md#screenkey와-720-매뉴얼-영향)를 따른다.

## 1. 프로젝트와 구성 준비

Project direct link는 기본 읽기 전용이다. 조회·Resource 상세·허용된 Excel 보고서는 편집 로그인과 구별한다. Task/Assignment/Target를 바꾸려면 해당 Project의 편집 권한을 열고, 공통 기준정보 변경에는 별도 관리자 권한을 사용한다. 비밀번호·세션은 URL에 넣지 않는다.

제품 표준 공정을 만들고 유효한 사업부–제품–사업장 관계에서 사업장별 공정 occurrence를 적용한다. 같은 제품의 두 사업장은 표준 공정을 공유하며 특정 사업장 추가 공정은 별도로 둔다. WorkArea는 선택 사항이고 하나의 사업장·제품·공정 occurrence 전용이다. WorkArea를 쓰지 않는 업무에 가짜 기본 구역을 만들거나 다른 공정의 구역을 공유하지 않는다.

프로젝트의 `기준정보 → 공정&WorkArea / 설비 / 물류 시스템`에서 기존 원본을 관리한다. 기존 Target를 사용할 때는 관련 기준정보의 보조 `Target 관리`에서 구성한다. Target는 별도 주메뉴나 새 업무의 필수 생성 단계가 아니며 자동 생성하지 않는다.  Target A에는 AMR10·ACS A, Target B에는 AMR5·ACS B를 놓고 공통 MCS는 기존 System 인스턴스 하나를 두 Target에서 재사용할 수 있다. 실제 같은 인스턴스를 이름만 바꿔 중복 등록하지 않는다. 시스템 종류 이름과 개별 인스턴스 label은 구별한다. 프로젝트 공통 Target은 명시적 `project_common`이며 임의 공정/WorkArea를 강제하지 않는다.

## 2. 같은 Task를 Target에 연결하기

실제 하나의 통합 업무는 하나의 Task를 여러 Target에 연결한다. 담당·기간·완료 기준이 다른 실제 업무일 때만 Task를 분리한다. Task Editor의 Target 연결에서 전체 구성원(whole) 또는 선택 구성원(subset)을 지정한다. ACS-only subset은 같은 Target의 AMR까지 포함하지 않는다. 작업 coverage는 실제 구성 수량과 별개이며 공수를 곱하는 값이 아니다.

기본 연결 범위는 self다. Summary는 subtree를 명시 선택할 수 있고 하위 Task는 직접 연결과 모든 조상 subtree의 합집합을 가진다. 하위 명시 연결은 상위 연결을 덮어쓰지 않는다. 직접/상속 출처를 확인하고, Target 구성 또는 WBS 이동으로 적용 범위가 달라지면 영향 확인을 거쳐 저장한다. 기존 직접 Equipment/System 연결만으로 Target를 자동 추정하지 않는다.

## 3. Resource에서 같은 원본 조회

`대시보드 → 리소스`에서 기간·Target·검색을 선택하고 추가 공정/WorkArea/설비·시스템 조건은 고급 필터에서 펼쳐본다. Resource 우선 Group→Resource→Target, Target 우선 Target→Group→Resource 및 비교표는 같은 원시 Task/Assignment의 조회 방식이다. 정렬·접힘·페이지·보기 전환은 WBS parent·Task 날짜·배정을 저장하지 않는다.

5근무일100% Assignment 하나가 A/B에 함께 연결되면 A5 M/D·B5 M/D지만 선택 A∪B 전체는5 M/D다. Target와 중첩 Group 소계를 더해 전체값을 만들지 않는다. AMR10+5는15대, ACS A/B는2식, 공유 MCS는1식이며 수량을 계획공수에 곱하지 않는다. 관련 계획공수는 원가 배분·실적·잔여공수가 아니다. Task 진척을 바꿔도 계획공수는 줄지 않는다.

| 범위·상태 | 읽는 방법 |
| --- | --- |
| T0 | 개인 조건 적용 전 선택 일반 Task 진단 범위. 개인 필터로 미배정을 숨기지 않음 |
| A | 선택 조건을 만족하는 원시 개인 Assignment. 한 Task 공동담당자는 별도 Assignment |
| R | Project 일반 Task 개인 배정 이력에 개인 분류 조건을 적용한 Capacity 모집단 |
| partial | 알려진 공수 부분합과 미설정 배정이 함께 있음. 확정 전체가 아님 |
| unset | 투입률 미설정. 공수 null/공란을0으로 읽지 않음 |
| configured0 | 설정된 배정이 비근무일 등으로0 M/D. unset/empty와 다름 |

| WorkArea 미사용 / 프로젝트 공통 | 공정에 구역을 지정하지 않은 상태와 project_common 예외를 구별 |

## 4. 원본 편집과 복귀

Task 행은 기존 Task Editor에서 이름·기간·상태·진척·Target 연결을 바꾼다. 정확 Assignment 행은 표시된 개인/Assignment ID의 배정 편집에서 기간·투입률을 바꾼다. Target 이름·구성은 Target composer에서 바꾸며 Task 이름 편집과 혼용하지 않는다. 가상 Group/Target 헤더·총계는 읽기 전용이다.

저장 후 같은 Task/Assignment ID의 다른 보기는 최신 snapshot으로 갱신되거나 stale를 표시한다. Resource→Editor/일정→Resource 복귀는 원래 조건·선택·펼침·상세·focus를 보존한다. 조건에서 탈락하거나 삭제된 행은 자동 복제/재연결하지 않고 유효한 컨트롤로 복귀한다.

pending 중 중복 저장하지 않는다. 취소·이동 시 dirty 초안 확인을 따르고 권한 만료401·기준 변경409/412에는 초안 보존/명시 폐기와 재조회 경로를 사용한다. 오류 응답을 저장 성공으로 간주하거나 mutation을 자동 재시도하지 않는다. Escape와 Tab/Enter는 현재 Editor/상세의 기존 닫기·복귀 순서를 따른다.

## 5. 주·월 Plan과 과투입 원인

Plan에서 선택 기여와 같은 개인의 Project 전체 참고를 구별한다. A80%와 다른 B60%이면 선택 A는80%, 같은 개인의 해당 Project 전체는140%다. 이는 전사 전체 부하가 아니다. Target/Task/기간 필터는 R를 줄이지 않는다. Resource Calendar를 적용한 고유 resource-day Capacity를 사용하고 Target/Group/Milestone에 반복 표시된 참고 Capacity를 합산하지 않는다.

주/월→일별→개인→정확 Assignment로 내려가 개인 Peak/초과를 확인한다. Group 평균이 정상이어도 개인이 초과할 수 있고 하루150%/다음0%는 평균75%라도 초과일이 있다. 미설정 allocation도 별도로 확인한다. Project 참고 원인은 출발 Target 밖 배정을 포함하며 출발 선택과 현재 참고 범위를 표시한다. 밖의 B 배정을 수정한 뒤 A 조건으로 돌아와 새 부하를 확인한다.

## 6. Excel과 안전한 교환

`Excel 보고서`에서 Resource 보고서 포함 및 current/project 범위를 명시한다. current는 같은 조건·source·snapshot, project는 확인된 기간/asOf/Calendar/M/M 정책을 유지하면서 개인/Task/Milestone/Target/공정/WorkArea/인스턴스·exact 제한을 제거한다. 이 선택은 추가 Resource 보고서에만 적용하며 기존 일정/Tasks 등은 Project 전체 기준이다.

기본7개 Resource 시트와 조건부4개 Target 근거 시트는 raw Assignment ID·M/D·M/M·null·기준 revision을 보존한다. 같은 Assignment가 여러 근거 행에 나와도 총계를 다시 더하지 않는다. stale export는 실패하므로 새 snapshot을 조회해 다시 요청한다. [Excel 형식](EXCEL_EXPORT.md)을 따른다.

Excel은 보고서이며 운영 백업/Target 무손실 재가져오기 형식이 아니다. Target-bearing plain 일정 Excel/일정 JSON은 현행 loss guard로 거부한다. Project Copy는 새 local ID를 만들고 global 참조는 재사용한다. Task binding 포함 Template는 logistics schemaVersion3, binding 없는 v2 및 legacy는 호환한다. 개인 Assignment가 있는 Task 복사는 현재 `TASK_COPY_ASSIGNMENTS_UNSUPPORTED`로 거부하며, 전체 Project Copy/Template와 지원 범위가 다르다. 다른 사업장으로 자동 이름 매핑/재배치된다고 가정하지 않는다. #379 전체 참조 JSON 미완료 및 [이관·복구 절차](TARGET_RESOURCE_OPERATIONS.md)를 확인한다.

## 프로젝트 리소스 등록과 해제

1. `기준정보 → 리소스`에서 이름·역할·등급·Group·등록/배정/비활성 조건으로 현재 프로젝트의 사용자를 확인한다. 목록에 없는 전역 사람도 등록 선택에서 찾을 수 있지만, 전역 전원이 자동 등록되지는 않는다.
2. 프로젝트 편집 잠금을 해제한 뒤 기존 사람을 선택해 등록한다. 같은 사람이 다른 프로젝트에 있어도 전역 원본을 새로 만들지 않는다. 등록한 사람이 작업을 맡지 않아도 목록에 남는다.
3. 기존 배정/설비 Owner/시스템 PI·개발자에서 발견한 사람은 사용 출처와 등록 필요 여부를 따로 확인한다. 역할이 있다는 이유만으로 모든 관련 Task를 그 사람의 투입으로 취급하지 않는다. 비활성 기존 참조는 보존하고 신규 등록은 활성 원본을 사용한다.
4. 작업을 맡기려면 기존 Task Editor의 리소스 배정을 편집한다. 배정된 사람과 진척0인 작업은 실제 수행/실적 공수의 증거가 아니다. 등록 인원2명·작업 배정1명은 정상이며 등록만으로 공수나 Capacity를 늘리지 않는다.
5. 해제는 이 프로젝트의 등록 관계만 제거한다. 사용 중이면 안내된 배정/책임 역할을 먼저 해당 편집기에서 명시 정리해야 한다. 과거 배정 이력을 자동 삭제하지 않으며 `/resources`의 전역 삭제와는 다른 동작이다. 다른 프로젝트 등록에는 영향을 주지 않는다.

읽기 전용에서는 조회/분석만 가능하다. 저장 중 중복 동작을 기다리고, 권한 만료는 잠금 해제 후, 충돌/다른 사람의 변경은 최신 내용을 조회한 후 다시 판단한다. Task·Assignment·책임 역할을 지우겠다는 명시 동작 없이 등록 해제를 위해 자동 정리하지 않는다. 지원 Copy/Template와 미지원 교환의 경계는 [교환 안내](IMPORT_EXPORT.md)의 #727 절을 따른다.

## KPI와 구성·연결 진단

1. **대시보드 → KPI**에서 기존 진척·지연·Milestone 경보·계획 투입 공수를 확인한다. 기준일/임박 기간·활성 대상·직접/조율 범위와 세부 공정/설비/System 탭은 계속 사용할 수 있다.
2. 통합 출처는 직접 연결·Summary 상속·기존 Target 연결을 같은 Task 원장에서 해석한다. Task 없는 등록 대상은 진척/공수가 없고, 미연결 일반 작업도 프로젝트 전체에는 포함된다. 신규 공정별 작업은 Task의 명시 공정이며 구성만으로 자동 분류되지 않는다.
3. 추가 구성/연결 진단을 펼쳐 등록 공정/구역·설비관리단위/수량·System·참여 인원과 작업0·미연결·개인 미배정·공수 미설정·Owner/PI/주제어 목록을 연다. 작업수/수량/공수/등록수는 별개다. WorkArea 미사용과 정상 미연결은 오류가 아닐 수 있다.
4. 정확 Task/Assignment에서 원본을 열거나 해당 작업 일정으로 이동한다. 기준정보는 해당 원본 관리로 이동한다. 조건과 출발 지점을 유지하고 복귀하며 최신 revision/source로 바뀌면 재조회 후 다시 선택한다. readonly에서는 기존 권한에 따라 조회하고 변경을 잠근다.
5. 기간 가중 진척은 설치완료 실적이 아니며 계획 M/D는 실적 공수가 아니다. M/M 환산 미설정과 null/설정0/알려진 부분합을 구별한다. 관련 Milestone은 선택 작업뿐 아니라 전체 소속·선행의 Gate다. E10이 여러 구역에 보여도 총10이며 동일5 M/D 배정의 공정 소계들을 더하지 않는다.

`screenKey=dashboard.kpi`에서 #720 매뉴얼로 연결할 기능 anchor다. 이 문서 갱신은 앱 내 `/manual` route/버튼 구현을 뜻하지 않는다. [기능 보존·검증 상태](exec-plans/active/ISSUE_731.md), [지표 사전](WBS_TASK_LEDGER.md#issue-731--kpi-consumer의-지표-인계)을 함께 확인한다.


## 동적 조회 구성과 정확 상세

대시보드에서 Milestone·공정&WorkArea·설비·물류 시스템·리소스를 선택하면 해당 항목이 조회의 맨 위에 고정됩니다. 보기 구성에서 하위 기준을 추가·삭제하고 위/아래로 이동한 뒤 적용하세요. 하위 없음은 선택 관점만 요약합니다. 공정 아래 설비와 시스템을 나란히 선택하면 같은 깊이에 표시되며, 실제 설비의 제어관계를 새로 만드는 동작이 아닙니다.

설비 관점에서 공정→물류 시스템→리소스 또는 Milestone→공정처럼 하위 기준을 바꿀 수 있습니다. 같은 Task가 여러 공정/구역 경로에 보이더라도 상위 작업수와 공수는 고유 원본 기준입니다. 설비10대가 두 구역에 보여도 상위 고유 수량은10대입니다. 구성 수량·작업수·개인 배정·계획공수와 전체 Milestone Gate는 서로 다른 단위입니다. 등록만 된 항목이나 미연결/미배정 행은 정상 조회 결과입니다.

표의 이름 찾기는 화면의 행만 좁히며 고유 총계는 전체 서버 조회 결과를 유지합니다. 작업 검색·기간·상태는 실제 서버 조회 조건입니다. 적용 기간과 기준일을 함께 확인하세요.

조회 설정은 현재 브라우저의 Project와 관점별로 보관됩니다. 업무 저장이나 다른 사용자의 설정 공유가 아니며 브라우저 자료를 지우면 없어질 수 있습니다. 잘못되거나 오래된 설정 안내가 나타나면 기본 보기로 복구하세요. 기간/검색/상태와 현재 경로를 확인하고 행의 정확 상세에서 Task 또는 개인 Assignment를 선택하면 기존 원본 편집 경로를 사용합니다. 조회용 미연결 그룹 자체는 편집할 수 없습니다.

원본이나 조회 조건이 바뀌면 이전 상세로 편집·일정 이동을 계속하지 않고 새로 조회합니다. 상세 닫기 또는 Escape로 출발 위치에 돌아갈 수 있습니다. 일정/원본 편집을 마친 뒤에는 이전 관점의 조건·펼침·선택을 유지하며 최신 snapshot을 확인합니다. readonly는 조회 구성과 상세 확인은 가능하되 기존 편집 권한을 넘는 저장은 허용하지 않습니다. 기존 KPI와 Milestone 관리·Resource Plan은 각각의 화면 기능을 계속 사용합니다. 새 계층 조회의 Excel은 아직 지원하지 않으며 기존 Excel로 조건을 생략해 내보내지 않습니다.

리소스 원본은 Project 참여/프로필과 관련 배정 상세를 엽니다. 전역 리소스 프로필 수정은 별도 관리자 권한입니다. WorkArea 원본은 공정 카탈로그의 같은 구역을 대상으로 하며 관리자 로그인이 필요할 수 있습니다. 로그인하거나 명시적으로 돌아가기 전까지 선택 대상을 유지합니다. 원본 창을 취소하면 출발 관점으로 복귀합니다.
