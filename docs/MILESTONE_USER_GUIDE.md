# Milestone 사용 가이드

이 가이드는 #549–#553 후보 구현의 사용자 흐름을 설명한다. main/운영 적용과 원격 회귀 상태는 [통합 추적표](MILESTONE_TIMELINE_TRACEABILITY.md)를 별도로 확인한다. 표시 변경은 원본 일정 저장이나 편집 권한 부여가 아니다.

## 일정에서 단계 확인

일정의 Grid와 Chart에는 Summary와 일반 Task가 표시된다. Milestone은 날짜축 위의 별도 Timeline에 표시된다. 일정 도구줄의 `◆ Milestone 표시`는 기본 ON이며 읽기 전용에서도 사용할 수 있다. OFF로 바꿔도 원본 단계·관계·소속·Summary 계산은 유지된다.

표시 설정은 프로젝트별 브라우저에 저장된다. 작업 검색·필터 초기화, Summary 범위와 상위 탭 전환은 표시 설정을 초기화하지 않는다. 저장소 오류가 나면 안내가 표시되고 현재 화면의 선택을 유지한다. 다른 브라우저나 프로젝트에는 같은 설정이 자동으로 전달되지 않는다.

Timeline의 전체 목록은 프로젝트 전체 Milestone이며 현재 Task 검색·WBS 범위의 개수가 아니다. 날짜에 단계가 없는 경우, 프로젝트에 단계가 없는 경우와 표시할 일반 Task가 없는 경우를 구별한다. 예정일이 미정인 단계는 날짜 위치로 표시할 수 없지만 전체 목록에서 확인할 수 있다.

## 상세와 같은 날짜 묶음

단일 marker에서 상세를 열거나 같은 날짜·근접 날짜 묶음을 열어 대상을 선택한다. 같은 이름도 외부 ID와 관리의 `작업 ID 복사`로 구분한다. 묶음 목록은 한 페이지 50개이며 다음 페이지로 나머지를 확인한다. 키보드 방향키·Home/End로 목록을 탐색하고 Enter로 상세를 연다. Escape는 현재 목록이나 상세를 닫고 가능한 원래 대상에 focus를 돌린다.

Milestone 대시보드에서도 해당 단계 행의 `상세`, `소속 작업`, `관리`를 사용한다. 관리는 상세·소속·관계·작업 ID 복사·해당 날짜/소속 작업 일정 보기와 허용된 단일 복사·삭제를 제공한다. Milestone 추가는 현재 Summary 범위와 무관한 프로젝트 최상위에 생성한다. 일반 Task의 native inline 편집은 유지되고, Milestone 이름·예정일·상태는 동일한 작업 정보 Editor에서 편집한다.

편집하려면 프로젝트의 편집 잠금을 해제해야 한다. 완료 단계의 구조·소속·관계 잠금과 서버 revision 검증은 그대로다. 저장 실패·권한 만료·다른 탭 변경은 자동 재전송으로 처리하지 않는다. 입력과 오류를 확인하고 명시적으로 다시 시도한다. 완료/재개 조건은 [단계 Gate](MILESTONE_STAGE_GATES.md), Editor 초안과 잠금은 [작업 정보](TASK_EDITOR.md)를 따른다.

## 소속 필터와 관계

일정의 `완료 단계` 필터는 해당 단계의 유효 소속 일반 Task와 필요한 Summary 문맥을 표시한다. Summary의 기본 소속을 자손이 상속할 수 있고 직접 지정이 있으면 그 지정이 우선한다. Milestone 표시 ON/OFF는 이 필터와 별개다. 결과의 일반 Task 일치 수, 직접 Summary 수, context Summary 수와 전체 WBS 수는 서로 다른 값이다.

작업 정보의 소속과 관계 탭은 전체 원본 집합을 사용한다. 표시에서 숨긴 단계도 기존 관계와 완료 조건에 계속 참여한다. 관계 Editor가 지원하지 않는 새 혼합 유형 관계를 화면에서 임의로 만들 수 없다. 보존된 과거 관계가 표시되거나 원형 Export에 포함되는 것과 새 생성/Import 지원은 다르다. [관계 계약](TASK_RELATIONS.md)을 따른다.

## 날짜와 원래 보기

대시보드 `해당 날짜에서 보기`는 현재 canonical ID와 예정일로 이동한다. 저장된 OFF에서 요청하면 일시적으로 표시하고, 원래 보기로 돌아갈 때 저장 OFF와 출발 Dashboard 조건을 보존한다. 명시 토글만 영구 설정을 바꾼다.

390px 등 좁은 화면에서 marker와 focus 외곽을 읽고 조작할 물리 폭이 부족하면 같은 ID의 전체 목록 행을 강조하고 그 관리 버튼에 focus를 옮긴다. 날짜가 없는 경우나 검색으로 대상 행이 제외된 경우는 별도 이유를 안내한다. 조건을 조용히 해제하거나 같은 이름의 다른 단계로 이동하지 않는다.

소속 작업 일정 이동과 Resource/Group에서 이동한 범위는 서버가 제공한 전체 고유 Task/Assignment 집합을 사용한다. 현재 상세 페이지의 50개만 전체 범위로 취급하지 않는다. 현재 WBS·필터와 충돌하면 확인하거나 취소한다. 원래 보기로 돌아가면 출발 조건과 페이지를 복원하며, 새 사용자 입력이 오래된 viewport 복원보다 우선한다. 복귀 순간 원래 조작 대상이 비활성이거나 사라졌으면 출발 탭에 focus를 돌리며 출발 조건과 상세 페이지는 유지한다.

## 내보내기 차이와 한도

`내보내기`는 화면의 Milestone 표시와 별개로 원본 일정 데이터를 출력하며 현재 Gantt 레이아웃과 다를 수 있다. OFF·검색·접기·선택 범위가 Milestone이나 소속 원본을 파일에서 제거하지 않는다. 새 Timeline 모양의 전용 renderer는 제공하지 않는다.

생성 중에는 형식·범위 옵션과 반복 실행, 닫기·Escape가 잠긴다. 생성 오류나 revision 충돌(412)이 발생하면 조건을 확인하고 명시적으로 다시 시도한다. 자동으로 재전송하지 않는다.

| 형식 | 출력 범위와 주의 |
| --- | --- |
| JSON 1.1 | 프로젝트 전체 일정·Dependency·명시 소속·Description/URL/Baseline을 보존한다. Resource와 Logistics는 제외하며 전체 운영 백업이 아니다. Task UUID는 원본 참고 metadata이고 새 프로젝트 Import는 UUID/FK를 재발급한다. 대상 Calendar를 적용하므로 원본 UUID·날짜 문자열의 단순 동일성을 재Import 보장으로 해석하지 않는다. |
| Excel | 기존 canonical 전체 Tasks/Gantt 및 소속·전체 Gate/공수 의미를 유지한다. 일정 Dependency 제외를 선택해도 명시/유효 단계·상속 출처가 출력된다. 추가 Resource 보고서는 opt-in이고 기존 일정·단계·물류 시트 범위를 바꾸지 않는다. |
| SVG | 전체 확장 WBS의 고정 작업명·시작일·기간 Grid와 Chart를 출력한다. 날짜 범위는 모든 행을 유지하고 차트 날짜축만 자른다. 현재 화면의 열 선택이나 Timeline lane을 그대로 캡처하지 않는다. |
| PNG | 같은 SVG 출력을 브라우저에서 변환한다. SVG와 같은 범위/지원 제한 외에 Canvas 크기·pixel 한도가 적용된다. |

과거 mixed Link를 원형 JSON으로 출력할 수 있어도 현재 Import는 지원하지 않는 조합을 전체 거부할 수 있다. 그런 경우 확인 안내를 읽고 원본 관계를 포함하는 다운로드를 명시적으로 선택한다. 모든 JSON이 다시 가져오기 가능한 파일이라는 보장은 없다. SVG/Excel 관계 포함의 지원 범위도 서로 다르며 지원하지 않는 관계·구조는 누락해서 성공시키지 않고 오류로 처리한다.

대표 한도는 JSON 5 MiB·Task 5,000·Dependency 20,000, Excel Task 5,000·Dependency 20,000·날짜축 3,650일·timeline cell 1,000,000이다. SVG는 Task 5,000·Link 20,000·날짜축 3,650일·cell 1,000,000·각 변 16,384px·16 MiB, PNG는 각 변 16,384px·32,000,000pixel 한도를 적용한다. 큰 출력은 지원하는 날짜 범위를 줄이거나 형식을 바꾼다. 일부 행·관계를 누락한 파일을 정상 전체 파일로 제공하지 않는다.

상세 지원/예산은 [JSON 교환](IMPORT_EXPORT.md), [Excel](EXCEL_EXPORT.md), [SVG/PNG](IMAGE_EXPORT.md)를 따른다. Windows Excel/DRM, 실제 보조기기·touch·운영 reverse proxy 검증은 Chromium 또는 서버 테스트와 별도다.
